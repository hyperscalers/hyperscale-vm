# Manifests and intents: the typed dataflow DAG

The manifest is the artifact every other layer reads: `route()` folds over it, admission type-checks it, wallets render it, solvers compose it, and effect signatures bind to it. Its design goal is that each of those consumers gets a read-off, never a reconstruction.

## 1. Structure

A manifest is a directed acyclic graph:

- **Nodes** are method invocations, typed against the target's declared signature ([05-runtime.md](05-runtime.md)). Arguments are literals, inbound edges, the intent's own sockets, or its members' gives (§3).
- **Edges** are typed value flows — resource amounts, proofs, plain data — each with exactly one producer and one consumer. Buckets are edges; proofs are edges. There is no ambient auth zone: evidence flows explicitly to the nodes that need it, and every claim it carries was attested by a gate that read state or by the shard keeping the account's own cell ([06-authority.md](06-authority.md)).
- **Linearity is well-formedness.** Every output edge must be consumed; a node's remainder (change from a partial take, residue after a swap) is a typed **rest edge** that must be routed somewhere, usually back to the sender's account. "Nothing dangles" is a syntactic check, not an execution-time discovery. SDK sugar auto-routes rest edges so the ergonomic cost lands in tooling, not on users.
- **Transient values are edge types.** A value whose type restricts its consumers to designated methods must be consumed like any edge, so the hot-potato pattern — flash loans, single-use rights — needs zero runtime machinery: the repayment obligation is unparseable to violate.
- **Constraints are declarative edge annotations** — minimum and maximum amounts, resource types. This is the same constraint language as an intent's sockets (§3): a slippage bound and an intent's "I accept ≥ 100 USDC" are one mechanism. The language stays enumerable and declarative — never a program — or admission-time checking erodes.
- **Sequencing is dataflow-only.** Execution order is the DAG's topological order; independent legs are visibly independent. Acyclicity is subsumed by the format: a manifest is acyclic or it does not parse.
- **Amounts are dynamic, types are static.** A swap-output edge's amount is runtime-determined; its resource type and constraints are not. Effects need types (which vaults), never amounts — the which-key/how-much split, carried into the format's type system.

**Fees are not in the manifest.** The fee payer, the `max_fee`, the per-node compute ceilings and the priority are the terms on the envelope, beside the tree (§3, [01-effects-and-routing.md](01-effects-and-routing.md) §8). There is no fee instruction of any kind.

## 2. What each consumer reads

- **`route()`**: a fold over nodes — evaluate each node's effect signature with its bound literals and inbound edge types, union the results. Order-independent by construction (INV-VM-ACCESS-5).
- **Admission**: type agreement between every node and its declared signature plus effect metadata; well-formedness (single producer and consumer per edge, acyclicity, constraint syntax); the tree's interface resolved and interleaved (§3). The parser and graph type-checker are more surface than an instruction-list decoder — a one-time toll at the layer where correctness matters most, and the admission checks are the bounded-decode discipline applied one level up.
- **Wallets**: the manifest *is* the asset-flow diagram to display — sources, transformations, destinations, and the user's own constraints — with no simulation and no instruction-trace recovery. Value movement is manifest structure, not call side effects, which is what makes signing legible and blind-signing structurally impossible.
- **The surface syntax** is SSA-style let-binding form — `let usdc = pool.swap(token); account.deposit(usdc)` — imperative to read, dataflow in denotation. The graph is the canonical (hashed, signed) encoding; the text form is a projection.

## 3. An intent composes intents

A transaction is one **intent**, and an intent is recursive: it may compose other intents, each nested inside it. A leaf composes nobody; the **root** is the intent nobody composes; a **member** is an intent some other intent composes, and every intent with members is a **composer**, whatever its depth. One type, one signing, one shape at every level.

An intent is a signed declaration of what one party wants:

- a **header** — the network it is declared for, its validity window, and a discriminator that tells two otherwise identical offers apart;
- the **accounts** it acts as, one or several, each signed in on its own shard under its own stored rule and each the owner of one of the intent's nullifiers;
- the principals whose keys **attest** it;
- its **graph** — one manifest over the calls it makes;
- its **interface** — the **sockets** it takes, and the **gives** it offers upward;
- its **members**, each a signed intent carried exactly as its signer handed it over, with the **wiring** that fills that member's sockets.

The intent's hash covers every member's hash, so signing an intent commits to the whole subtree beneath it. Nesting rather than naming is what makes the structure fool-proof: a composer physically contains its members, so order, reachability, sharing and cycles are not rules admission states and refuses but shapes the value cannot take, and no edit to a member can desync anything above it. A given intent hash appears at most once in a tree, and the tree nests at most eight deep.

**Value is exchanged; authority is delegated.** A value edge is finite and enumerated: an intent knows what it puts up, and its own constraints bound what it must get back, so it can trade with a stranger it will never see. A claim is open-ended — it satisfies any gate naming its subject, and no signer can enumerate those in advance. So value crosses a trust boundary and authority does not, and the interface is built on that split.

- **A socket is a hole the composer fills.** A value socket names a resource and the declaring intent's constraints on it; an authority socket names a *claim*. The declaration says what may arrive and its signer signs that; the composer says whose, in wiring the composer signs and the declaring party never sees. A value socket is consumed by exactly one node argument of the declaring graph or passed on to exactly one member's socket; an authority socket is presented by as many nodes, and granted on to as many members, as ask for it.
- **A give is value offered upward, and value alone.** There is no give that carries a claim: authority has no channel upward and no field in which to write the hazard. A composer takes a member's give as an argument of its own graph, wires it into a sibling's socket, or gives it on as its own — and each give is taken exactly once above the intent that declares it.
- **A composer names only a member's published interface.** Its wiring sources from its own graph's edges, its members' gives, its own sockets passed through, and the claims it holds; no node index of a member's graph appears anywhere in the composing intent. That is what makes a sealed group indistinguishable from a leaf: a group that composes a quote and re-exports its socket and its give is, to whoever composes the group, exactly the quote.
- **A grant is confined to scope.** An account's claim may be granted into a member's socket only by an intent that holds it: one that acts as the account, or one that received the claim in a socket of its own. Since an intent wires only its own members, a claim reaches a distant descendant by being re-granted at every level, by someone who signed that level. The three relationships fall out of the one rule: an intent that signed nothing above itself grants nothing, so a detached offer is inert; the root grants anywhere beneath it; and two accounts that both sign one intent each hold the other's claim in scope. A grant is per use — a declared socket and an explicit wiring — never ambient: a member signed before its composer existed cannot have a gate quietly answered by a claim it never asked for. Nothing proves a granted account's claim and no node carries it, so the socket it fills waits on nothing.
- **Several accounts, one intent.** A call gated on two accounts sits in one intent both signed, and no authority crosses a boundary at all. Every account an intent acts as sits on a shard the core waits on, and a node presenting a claim off that claim's own shard is the core's — which is what makes a granted claim safe under decomposition, at the cost that deep trees increasingly run whole ([08-host-integration.md](08-host-integration.md) §3).
- **Attestation is a set of keys over one declaration.** An intent declares the principals whose keys attest it, in signed content; each attestation stands beside the content it covers — a member's inside the signed intent its composer places, the root's on the transaction envelope — pairing by position and never across structures. Each account's shard judges its own stored rule against that one set, so a threshold is a property of one intent and is never folded across intents: a composer holding two intents Alice signed with one key each cannot make them satisfy her two-of-two together. Whether the keys may act as the account is that shard's question ([06-authority.md](06-authority.md) §5), not admission's.
- **Once-only by nullifier.** Committing an intent writes one nullifier substate per account it acts as, at a canonical address under that account, keyed by the intent's hash and its window's end; existence is spent. The address is computable, hence declared; that account's shard participates anyway; and two transactions racing one intent contend on the nullifier key — exactly one commits, the other aborts deterministically. Expiry rides the intent's own weighted-time window plus the retention grace. A nullifier is written by a commit and by nothing else: an aborted transaction spends no intent's, so a composer cannot retire a counterparty's signed offer by carrying it in a tree that fails.

**The transaction envelope is transport.** It carries the tree whole — the root with every member nested inside it — and beside it the **terms**: the payer, the fee ceiling, the per-node compute ceilings, the priority, and an optional message ([01-effects-and-routing.md](01-effects-and-routing.md) §8). The root's attestations cover the envelope's digest — the tree, the terms, and for a publish the artifact — and that digest is the transaction hash. The terms stay out of every intent's hash, because how a transaction is paid is not what it does: the same tree resubmitted at a higher ceiling contends on the same nullifiers rather than running the declaration twice. A publish is a root that calls nothing, with the artifact beside it. The terms are a function of the assembled manifest, so only the root's attesters can sign them; that is why the payer is the root's and never a member's. Per-member payers would create circular commit-proof dependencies among multiple first-committing shards ([08-host-integration.md](08-host-integration.md) §2), so the whole envelope's terms are one party's, and a member contributes to the cost **in band or not at all** — a bounded edge to the payer inside the same transaction, constrained like any other edge and settled by the same atomicity. Root-paid fees plus deferred bonds compose into gasless onboarding ([03-objects-and-state.md](03-objects-and-state.md) §4).

**Admission resolves the whole interface layer.** It walks the tree in preorder, follows every socket and every give to the node or the account that ultimately stands behind it, judges every grant against the granter's scope, and interleaves the tree into one flat manifest — the same list the classifier, leg planning and the kernel read whatever the tree's depth. An intent that both gives and takes is interleaved node by node: the node producing its give runs before the composer consumes it, the node consuming its socket after the composer fills it, so a cycle between intents is a DAG over nodes and coroutine-shaped counterparty protocols stay expressible while the format stays acyclic. Every transaction is a tree; an ordinary transfer is a tree of one leaf.

**Composition is graph gluing.** Structurally, a member is a sub-DAG and a socket or a give is an edge crossing a signing boundary. Referential transparency is structural: no register state leaks between intents, so a composer adds edges *between* graphs and can never change the meaning of the edges *within* one — "bound, never altered" made literal. The primitive exists because static access evicts choice-making to signing time: solvers compose users' intents off-chain, and the split bounds their power to composition, never custody.

## 4. Lineage

The format keeps, deliberately: asset-orientation (value movement as structure); code-free composition (chaining components atomically with no deployed glue contract); transaction-level assertions, generalized to edge constraints; transaction-layer linearity, generalized to total edge consumption; explicit auth evidence and per-intent isolation. It rejects the ambient mutable worktop — an instruction register that makes meaning depend on encoding order and turns static analysis into abstract interpretation — along with untyped-until-runtime call boundaries and fee instructions in the payload. From Sui's programmable transaction blocks it takes explicit result references with no ambient store, and leaves the sequential command encoding and the absence of a constraint language.
